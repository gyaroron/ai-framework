# Mini Redis — 인메모리 캐시 서버

C99로 작성한 키-값 저장소(key-value store)와 TCP 서버입니다. 해시 테이블(hash table)에 문자열을 보관하고, RESP 요청을 받아 `PING`, `SET`, `GET`, `DEL`을 처리합니다. 서버는 `select`를 이용한 단일 스레드(single-threaded) 비차단(nonblocking) 루프에서 여러 연결을 다룹니다.

- `SET`은 키와 값을 복사하여 저장하고, 같은 키가 있으면 값을 바꿉니다.
- `GET`은 저장된 값을 반환하며 없는 키에는 RESP null bulk string을 응답합니다.
- `DEL`은 삭제 성공 여부를 1 또는 0으로 응답합니다.
- `PING`은 `PONG`을 보내거나 전달받은 인자를 돌려줍니다.

## 실행 방법

아래 명령은 `mini_redis` 디렉터리에서 실행합니다. TCP 서버는 POSIX 소켓 API를 사용하므로 Linux 환경과 C 컴파일러, `make`가 필요합니다. 명령은 Makefile에서 확인했으며 이번 작성 중 실행 결과는 확인하지 않았습니다.

```bash
make              # mini_redis 빌드
./mini_redis      # 해시 테이블 생성·삽입·조회·갱신·삭제 확인
make test         # RESP 파서의 완성·부분 수신·연속 요청 테스트
./mini_redis --server  # TCP 6379 포트에서 서버 실행
```

서버를 실행한 뒤 다른 터미널에서 `redis-cli -p 6379 PING`, `redis-cli -p 6379 SET name John`, `redis-cli -p 6379 GET name`을 차례로 보내 `PONG`, `OK`, `John`을 확인할 수 있습니다. 이 명령은 별도로 설치된 `redis-cli`가 필요하며, 여기서는 실행하지 않은 확인 절차입니다.

## 폴더 구조

```text
mini_redis/
├── hashtable.c / hashtable.h  # 16개 버킷의 해시 테이블과 문자열 소유권
├── resp.c / resp.h            # bulk string 배열 형태의 명령 파서
├── server.c / server.h        # select 기반 TCP 서버, 응답 작성, 명령 처리
├── main.c                     # 해시 테이블 확인과 서버 실행 진입점
├── test_resp.c                # RESP 파서 테스트 세 가지
├── Makefile                   # 빌드, 테스트, valgrind, 정리 명령
└── README.md                  # 해시 테이블 API와 포인터 수명 설명
```

## 데이터 흐름

```text
TCP 수신 → 클라이언트 입력 버퍼 → RESP 명령 파싱
                              ├─ 미완성: 다음 수신까지 보관
                              ├─ 오류: 오류 응답을 보낸 뒤 연결 종료
                              └─ 완성: PING / SET / GET / DEL 처리
                                       ↓
                              해시 테이블 읽기 또는 변경
                                       ↓
                              응답 버퍼 → TCP 전송
```

입력 버퍼에 요청이 여러 개 있으면 완성된 요청을 하나씩 처리하고 남은 바이트를 앞으로 옮깁니다. 각 요청은 같은 테이블을 사용합니다.

## 핵심 개념

### 1. 해시와 충돌 처리

`ht_hash`는 키의 각 바이트를 읽으며 `hash = (hash * 31 + byte) % 16`을 계산합니다. 같은 버킷(bucket)에 서로 다른 키가 들어오면 단일 연결 리스트(singly linked list)로 이어서 보관하고, 조회할 때 키를 비교하며 찾습니다. 따라서 키가 한 버킷에 몰리면 해당 리스트를 길게 순회할 수 있습니다. 16개 버킷은 고정되어 있어 데이터가 늘어도 자동 확장되지 않습니다.

### 2. 문자열 소유권과 포인터 수명

테이블은 `SET`에 전달된 키와 값을 새 메모리에 복사합니다. 기존 값을 바꿀 때는 새 값 복사에 성공한 뒤 이전 값을 해제합니다. `ht_get`이 반환하는 포인터는 테이블이 소유한 값을 가리키므로 해당 키의 값 갱신·삭제 또는 테이블 해제 뒤에는 사용할 수 없습니다.

### 3. RESP 요청과 응답

파서(parser)는 RESP의 모든 자료형을 일반적으로 해석하는 구현이 아닙니다. bulk string만 원소로 갖는 비어 있지 않은 배열 형태의 명령을 읽고, 완료·미완성·오류를 구분합니다. 요청 인자 수는 최대 1024개이며 개별 bulk 길이 제한은 1 MiB입니다. 다만 서버의 입력 버퍼는 64 KiB이므로 실제 서버에서 수용할 수 있는 요청 크기는 더 작습니다.

| 명령 | 인자 | 응답 예 |
|---|---|---|
| `PING` | 없음 또는 문자열 하나 | `+PONG\r\n` 또는 bulk string |
| `SET` | 키와 값 | `+OK\r\n` |
| `GET` | 키 하나 | bulk string 또는 `$-1\r\n` |
| `DEL` | 키 하나 | `:1\r\n` 또는 `:0\r\n` |

### 4. 단일 스레드 이벤트 루프

서버는 `select`로 읽거나 쓸 준비가 된 소켓을 찾고, 요청을 한 번에 하나씩 처리합니다. 처리 순서가 한 실행 흐름에 놓이는 것과 해시 테이블 자체가 스레드 안전(thread-safe)한 것은 다릅니다. README는 테이블이 스레드 안전하지 않다고 밝히므로 다른 멀티스레드 코드에서 공유할 때는 별도 동기화가 필요합니다.

## 입력 검사와 엣지 케이스

| 상황 | 코드에서 확인한 처리 |
|---|---|
| 같은 키에 다시 `SET` | 새 값 복사 성공 후 기존 값을 교체 |
| 없는 키의 `GET` / `DEL` | null bulk string / 정수 0 |
| 요청 일부만 도착 | 파싱을 보류하고 입력 버퍼에 남김 |
| 잘못된 RESP 형식 | `-ERR Protocol error`를 쓴 뒤 연결 종료 |
| 허용하지 않는 명령 또는 인자 수 | 오류 응답 |
| 입력 버퍼가 가득 참 | `request too large` 응답을 쓴 뒤 연결 종료 |
| 여러 요청이 한 번에 도착 | 완성된 요청을 순서대로 처리 |

## 알려진 한계와 확인 범위

- 데이터는 프로세스 메모리에만 있으며 디스크 저장과 만료 시간(TTL) 처리는 코드에서 확인되지 않습니다.
- RESP 파서는 bulk string 배열 명령에 한정됩니다. `strlen`과 `strcmp`를 쓰므로 NUL 바이트를 포함한 임의의 바이너리 값은 보존하지 못합니다.
- `DEL`은 키 하나만 받습니다. 전체 Redis 명령이나 프로토콜 호환을 주장할 수 없습니다.
- `make test`는 `test_resp.c`의 세 파서 사례를 실행하며 해시 테이블 전체나 네트워크 동작을 검증하지 않습니다. 인자 없는 `./mini_redis`는 별도의 다섯 단계 해시 확인을 수행합니다.
- `make valgrind` 대상은 인자 없이 프로그램을 실행합니다. 이번 작업에서 누수 검사나 서버 통합 테스트는 실행하지 않았으므로 결과는 미확인입니다.

# Version 2 — 국문 설명

# Mini Redis — 인메모리 캐시 서버

C99로 만든 키-값 저장소와 TCP 서버입니다. 메모리에 문자열을 저장하며, 클라이언트의 `PING`, `SET`, `GET`, `DEL` 요청을 처리합니다. 서버는 하나의 실행 흐름에서 여러 연결의 읽기와 쓰기를 살핍니다.

- `SET`: 키와 값을 복사해 저장하거나 기존 값을 바꿉니다.
- `GET`: 키에 해당하는 값을 읽으며, 키가 없으면 빈 결과를 보냅니다.
- `DEL`: 키를 지우고 성공 여부를 1 또는 0으로 보냅니다.
- `PING`: `PONG` 또는 전달받은 문자열을 보냅니다.

## 실행 방법

Linux 환경에서 `mini_redis` 디렉터리로 이동한 뒤 다음 명령을 실행합니다. 이번 문서 작성 중 실행하지 않았으므로 결과는 미확인입니다.

```bash
make                  # 프로그램 빌드
./mini_redis          # 해시 테이블 다섯 단계 확인
make test             # 요청 분석기 테스트
./mini_redis --server # 6379 포트 서버 실행
```

다른 터미널에서 `redis-cli -p 6379 PING`, `redis-cli -p 6379 SET name John`, `redis-cli -p 6379 GET name`을 차례로 실행하면 `PONG`, `OK`, `John`을 확인할 수 있습니다. 별도로 설치된 `redis-cli`가 필요하며 위 절차는 여기서 실행하지 않았습니다.

## 폴더 구조

```text
mini_redis/
├── hashtable.c / hashtable.h  # 해시 테이블과 문자열 보관
├── resp.c / resp.h            # 요청 분석
├── server.c / server.h        # 연결, 명령 처리, 응답 전송
├── main.c                     # 자체 확인과 서버 실행
├── test_resp.c                # 요청 분석 테스트
├── Makefile                   # 빌드와 테스트 명령
└── README.md                  # 테이블 사용법
```

## 데이터 흐름

```text
요청 수신 → 입력 보관 → 요청 분석 → 명령 처리 → 응답 보관 → 응답 전송
                         ├─ 미완성: 나머지 수신 대기
                         └─ 형식 오류: 오류 응답 후 연결 종료
```

완성된 요청이 여럿이면 앞에서부터 차례대로 처리합니다. 값의 읽기와 변경에는 같은 해시 테이블을 사용합니다.

## 핵심 개념

### 1. 키를 찾아가는 방법

키의 바이트를 차례로 계산하여 16개 칸 가운데 하나를 고릅니다. 서로 다른 키가 같은 칸을 고르면 연결 목록에 함께 보관하고, 찾을 때 목록을 따라가며 키를 비교합니다. 한 칸에 키가 몰릴수록 살펴볼 항목이 늘어나며, 칸 수는 자동으로 늘어나지 않습니다.

### 2. 누가 문자열을 보관하는가

테이블은 전달받은 키와 값을 복사하여 따로 보관합니다. 기존 값을 바꿀 때 새 복사본을 먼저 만든 뒤 이전 값을 해제합니다. 조회 결과는 테이블 안의 값을 가리키므로 해당 값을 바꾸거나 지운 뒤, 또는 테이블을 없앤 뒤에는 사용할 수 없습니다.

### 3. 요청 형식과 응답

요청 분석기는 모든 RESP 자료형을 해석하지 않고, 문자열 묶음으로 이뤄진 비어 있지 않은 배열을 명령으로 받습니다. 요청 하나의 인자는 최대 1024개이며 한 문자열의 분석기 길이 제한은 1 MiB입니다. 서버 입력 공간은 64 KiB이므로 서버를 거치는 요청은 이보다 더 작아야 합니다.

| 명령 | 보내는 내용 | 돌아오는 내용 |
|---|---|---|
| `PING` | 인자 없음 또는 문자열 하나 | `PONG` 또는 보낸 문자열 |
| `SET` | 키와 값 | 성공 응답 `OK` |
| `GET` | 키 하나 | 값 또는 빈 결과 |
| `DEL` | 키 하나 | 삭제 여부 1 또는 0 |

### 4. 여러 연결을 다루는 방법

서버는 `select`로 준비된 연결을 찾고 하나의 실행 흐름에서 요청을 차례로 처리합니다. 해시 테이블을 다른 다중 실행 흐름 프로그램에서 공유해도 안전하다는 뜻은 아닙니다. 테이블 설명서는 별도 보호 없이 여러 흐름에서 함께 사용할 수 없다고 밝힙니다.

## 입력 검사와 예외 상황

| 상황 | 코드에서 확인한 처리 |
|---|---|
| 같은 키를 다시 저장 | 새 값을 복사한 뒤 이전 값을 교체 |
| 없는 키를 읽거나 삭제 | 빈 결과 또는 0 반환 |
| 요청이 나뉘어 도착 | 남은 부분이 올 때까지 보관 |
| 요청 형식 오류 | 오류를 보낸 뒤 연결 종료 |
| 지원하지 않는 명령이나 잘못된 인자 수 | 오류 응답 |
| 입력 공간이 가득 참 | 요청이 크다는 오류를 보낸 뒤 연결 종료 |
| 여러 요청이 함께 도착 | 완성된 요청을 순서대로 처리 |

## 알려진 한계와 확인 범위

- 값은 메모리에만 저장합니다. 디스크 저장과 만료 시간 처리는 코드에서 찾지 못했습니다.
- 요청은 문자열 배열로 제한됩니다. 문자열 처리 방식 때문에 중간에 NUL 바이트가 들어간 임의의 이진 값은 보존하지 못합니다.
- `DEL`은 키 하나만 받으며 전체 Redis와의 호환은 확인하지 않았습니다.
- `make test`는 요청 분석기의 세 사례를 실행합니다. `./mini_redis`의 다섯 단계 해시 확인과 서버 통신 확인은 별개입니다.
- 이번 문서 작성 중 빌드, 테스트, 메모리 누수 검사, 서버 통신을 실행하지 않았으므로 그 결과는 미확인입니다.
